# Project Brief — Compressed Medical MT Benchmark (en→fi)

> Verbatim copy of the original brief, kept as the spec of record. Progress is
> tracked against it in `docs/progress.md`. Do not edit this file except to fix
> transcription errors — propose changes in `docs/progress.md` instead.

---

Hand this to a coding agent as the initial instruction set. It is a specification, not a README. The README is a **deliverable produced at the end** (Phase 6) and should contain results, not instructions.

---

## Goal

Build a self-hosted English→Finnish medical translation service and measure what quantization does to translation quality — especially to safety-critical content like dosages, drug names and negations.

The output that matters is **a table of measured results**, not a working API. The API is the last and least important piece.

---

## Non-goals

Do not build any of these. They will expand to fill all available time.

- A web frontend or UI of any kind
- User accounts, authentication, rate limiting, database persistence
- A training pipeline from scratch — fine-tuning only
- Support for language pairs other than en→fi
- Kubernetes, CI/CD, cloud deployment

---

## Standing rules

1. **Never evaluate on data the model was trained on.** Deduplicate before splitting. Split once, then leave the test set alone until measurement.
2. **Fix random seeds. Pin every dependency version.** Record both in every results file.
3. **Every latency number names the hardware it was measured on.** CPU model, core count, thread count, RAM.
4. Results are written to disk as JSON or CSV as they are produced, never only printed.
5. Run every new script on a 100-sentence subset before running it on the full test set.
6. Prefer boring, readable code. This is measurement infrastructure, not a product.

## Phase 0 — Smoke test

Install the environment. Download `Helsinki-NLP/opus-mt-en-fi`. Translate ten English sentences you write by hand and print the Finnish output.

**Done when:** ten sentences translate and look like Finnish.

---

## Phase 1 — Data

Download EMEA en–fi. Easiest source is the `Helsinki-NLP/emea` dataset on Hugging Face.

`src/prepare_data.py` must:

1. Load the raw pairs.
2. Drop pairs where either side is empty, or where the length ratio between sides is implausible.
3. **Deduplicate on the source sentence.** EMEA is extracted from medicine-leaflet PDFs and repeats heavily. Report how many pairs were removed — this number goes in the README.
4. Split into train / dev / test. Test is 2000 pairs. Write all three to `data/processed/` as plain parallel text files.
5. Write a JSON summary: counts before and after each step, seed used.

**Critical:** deduplicate before splitting, not after. If identical sentences land in both train and test, every result from Phase 4 onward is worthless.

**Done when:** three split files exist and the duplicate-removal count is recorded.

---

## Phase 2 — Baseline and compression sweep

This is the decision point of the whole project. Do it before anything else optional.

Two base models:

- `Helsinki-NLP/opus-mt-en-fi` (~75M parameters, Marian architecture)
- `facebook/nllb-200-distilled-600M`

`src/convert.py` converts each to CTranslate2 at every supported precision:

- `float32`, `int16`, `int8`
- `float16`, `bfloat16` additionally if a GPU is available

**Known gotcha:** NLLB requires explicit language tokens. Source language `eng_Latn`, target `fin_Latn`. It will produce nonsense without them. Marian does not need this. Handle both cases in `translate.py`.

`src/translate.py` translates the test set with a given converted model and writes output plus timing to `results/`.

`src/evaluate.py` scores a translation file against the reference:

- BLEU and chrF++ via sacrebleu
- **Paired bootstrap resampling with confidence intervals** — sacrebleu implements this. Bare score deltas are not acceptable output.
- COMET via `unbabel-comet`

For each condition record: BLEU, chrF++, COMET, all with CIs; translation time; model size on disk; peak memory.

Then plot quality against precision for both models.

**Done when:** a results table exists covering both models at every precision, and there is a plot. Interpret it before continuing:

- **Curve bends** → good, proceed.
- **Curve is flat** → expected for Marian int8. Do not stop. Phase 3 is where the signal probably is, and NLLB may behave differently. Proceed to Phase 3 and re-read the results after.

## Phase 3 — Entity checks

`src/entity_checks.py` compares each translation against its reference and counts three error classes. Run across every condition from Phase 2.

**Numeric fidelity.** Every number and unit in the source appears in the output, unchanged. "5 mg" must stay "5 mg". This is the easiest check and probably the most important.

**Negation preservation.** Harder in Finnish than in English. Finnish negation uses the verb *ei*, which inflects for person and number (*ei, eivät, älä*, and so on), and the main verb takes a connegative form. A regex for "not" will not work. Start with a list of negation verb forms plus common constructions like *ei saa* and *ei tule*, accept that it will be imperfect, and manually validate the checker on 100 sentences before trusting it. Document its accuracy.

**Drug-name presence.** Drug names inflect in Finnish, so exact string matching will produce false negatives. Match on the stem, or on the first several characters of the name. Again, validate manually and document the error rate of the checker itself.

Report counts as proportions with bootstrap confidence intervals — these are binary outcomes, not scores, so BLEU-style treatment is wrong.

**Done when:** every condition has entity error counts with CIs, and each checker's own accuracy is documented.

The interesting result is aggregate scores staying flat while entity errors climb. If that appears, it is the headline finding.

## Phase 4 — Fine-tuning

Write `src/filter_config.yaml` for OpusFilter to clean the **training split only**. It is filtering PDF extraction damage: broken tables, page headers, misaligned pairs, sentences in the wrong language. Use OpusFilter's language identification and length-ratio filters as a starting point.

`src/finetune.py` fine-tunes each base model on the filtered medical training data using HuggingFace `Seq2SeqTrainer`. Marian is small enough for one consumer GPU. Save to `models/hf/`.

Then re-run Phases 2 and 3 unchanged on the fine-tuned models.

**Done when:** the full results table exists — two base models × two adaptation states × every precision level, with quality scores, entity errors and timing.

---

## Phase 5 — Service

`service/app.py`: FastAPI, one `POST /translate` endpoint taking `{"text": "..."}` and returning `{"translation": "..."}`. Load the CTranslate2 model once at startup using the lifespan pattern, not per request.

`service/Dockerfile`: model baked into the image, no network access at runtime.

Nothing else. No streaming, no batching endpoint, no metrics endpoint.

**Done when:** `docker run` starts it and it translates with networking disabled.
